# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**MapGame** — a casual puzzle-roguelike for iOS/Android: explore a hex grid map where every move costs food (movement cost = Chebyshev distance), tiles hide events (Battaglia/combat, NPC, Mistery, Risorsa), and you lose by running out of food or dying. Built on Unity 2022.3.62f3 + URP, on top of the in-house **"55HP Games Unity Mobile Template"** (a reusable service-based mobile game architecture — see `Assets/Documentation/`).

This is a Unity Editor project — there is no npm/CLI build. Work is done by editing `.cs` scripts, `.asset`/`.prefab`/`.unity` assets, and driving builds/tests through the Unity Editor (or `Unity.exe -batchmode` if scripting CI).

## Commands

There is no package-manager build/lint/test CLI. Common workflows:

- **Open the project**: Unity Hub → open with Editor version `2022.3.62f3` (must match `ProjectSettings/ProjectVersion.txt` exactly, or Unity will reimport/upgrade).
- **Run tests**: Unity Editor → Window → General → Test Runner. EditMode tests live in `Assets/Tests/EditMode/`, PlayMode tests in `Assets/Tests/PlayMode/`. There is no headless CLI test runner configured in this repo; run tests from the Editor's Test Runner window (or `-runTests -testPlatform` batchmode flags if invoking Unity.exe directly).
- **Custom editor tools** (Editor menu, under `hp55games Tools/`): `HP55_TemplateAudit` (Export Template Audit), `HP55_StaticScan` (Static Scan/Run), `HP55_FileTreeScan` (File Tree/Export), `HP55_ScriptExporter`, `HP55_LocalizationTableEditor`, `HP55_CommandSequenceCreator`, `HP55_Mesh3DToCollider2DTool`. These are diagnostic/export utilities, not build steps — use them when asked to audit the template or export scripts/localization data.
- **Solution/csproj files** at the repo root are Unity-generated (regenerated by the Editor/Rider) — don't hand-edit them.

## Architecture

### Assembly layout

Code is split into asmdef-defined assemblies, roughly:

- `Core.Runtime` (`Assets/Core/Runtime/`) — the reusable template: architecture, bootstrap, audio, config, save, pooling, scene flow, localization, input, options, gameplay primitives (damage/movement/spawning). Namespace root: `hp55games.Mobile.Core.*`.
- `UI.Runtime` (`Assets/Core/Runtime/UIScripts/`) — UI framework (navigation, popups, overlays, toasts, HUD).
- `Game.Features` (`Assets/MapGame/Features/`) — MapGame-specific gameplay: hex grid, camera, hints, UI screens/popups. Namespace root `hp55games.MapGame.Features.*` (note this differs from the `Core.Runtime`/`UI.Runtime` root of `hp55games.Mobile.Core.*` — the assembly name `Game.Features` is a holdover from the template's original naming, but the namespace was renamed to `MapGame` for this project).
- `MapGame.Features.HexDebugAdapter` — glues the hex grid gameplay code to the standalone `hp55games.Tools.HexDebugFramework` package (below).
- `hp55games.Tools.HexDebugFramework` (`Assets/HP55GamesTools/HexDebugFramework/`) — a generic, game-agnostic hex-grid debugging/visualization tool (scene overlay drawing, analyzers, debug windows). It only knows about `IHexCell`/`IHexTopology`/`IHexAnalyzer` interfaces; MapGame-specific analyzers (reachability, cluster budget, neutral separation, event-cluster spacing) live in `Game.Features`'s `HexDebugAdapter` folder and implement those interfaces.
- Each Runtime assembly has a matching `.Editor` assembly for editor-only tooling (inspectors, custom editor windows) — keep editor code out of runtime assemblies.
- `Assets/Editor/` (no asmdef — Assembly-CSharp-Editor) holds project-wide `HP55_*` tools not tied to a specific feature.

### Bootstrap & scene flow

The game always starts from `Assets/Scenes/00_Bootstrap.unity`. `GameBootstrap` (`Core.Runtime/Bootstrap/GameBootstrap.cs`):
1. Calls `ServiceRegistry.InstallDefaults()` to register all core services.
2. Loads `config/scene_flow_config` via Addressables and registers `ISceneFlowConfig`.
3. Additively loads, in order: `90_Systems_Audio` → `91_UI_Root` → `01_Menu`, waiting for each to finish before continuing.
4. Waits for `UIRuntime.ServicesReady` (set by `UIServiceInstaller` in `91_UI_Root`) before the game is considered ready.

`ServiceRegistry` (`Core.Runtime/Architecture/ServiceRegistry.cs`) is a minimal static service locator: `Register<T>(instance)` / `Resolve<T>()` / `TryResolve<T>()`. All cross-cutting systems (logging, event bus, config, save, addressables content loading, state machine, pooling, options, localization, input) are resolved through it — there is no DI container/attribute injection, so new services must be registered explicitly in `InstallDefaults()`.

Game flow after bootstrap runs through an async `IGameStateMachine` (`Core.Runtime/Architecture/GameFSM/`) with states in `Core.Runtime/Architecture/States/` (`MainMenuState`, `GameplayState`, `PauseState`, `ResultState`). States implement `EnterAsync`/`ExitAsync` and are switched via `fsm.ChangeStateAsync(new SomeState())`.

### UI system

UI lives entirely under an additive scene, `Scenes/Additive/91_UI_Root`, structured as `UIRoot/Canvas` with fixed layers: `Layer_HUD`, `Layer_Pages`, `Layer_Popups`, `Layer_Overlay`, `Layer_Toasts`. Each UI service (`IUINavigationService`, `IUIPopupService`, `IUIOverlayService`, `IUIToastService`) only ever touches its own layer, and every UI element is an Addressable prefab loaded by address — never by direct scene reference. Addressable keys are centralized as constants in `hp55games.Addr` (`Core.Runtime/Utils/Addr.cs`) rather than as scattered string literals — always add new UI/audio/config addresses there instead of inlining address strings.

Addressable key convention: `content/ui/pages/<name>`, `content/ui/popups/<name>`, `content/ui/overlays/<name>`, `content/ui/toasts/<name>`, `content/audio/bgm/<name>`, `config/<name>`.

### Audio

`IMusicService` (background music) uses a dual-`AudioSource` crossfade player (`MusicPlayer` prefab in `90_Systems_Audio`); both sources must be looping with `playOnAwake = false`. `AudioOptionsBinder` wires the persisted `IUIOptionsService` (volumes/mute/haptics/language, saved through `ISaveService`) into the Audio Mixer's Music/SFX groups automatically — don't hand-roll volume application logic.

### Hex grid gameplay (MapGame-specific)

Core hex logic lives in `Assets/MapGame/Features/Gameplay/HexGrid/`: `HexCoord` (coordinate math), `HexGridController` (grid state/interaction), `HexTileData`/`HexTileView` (per-tile model/view), `HexTileTapController` (input), `IMapGenerator` + `AestheticClusterMapGenerator` + `MapGenerationService`/`Installer` (procedural map generation using event clusters, configured via `Assets/MapGame/Content/Configs/`). Encounters/events raised while exploring flow through `EncounterEvents` into UI (`EncounterPopupTrigger` → `UIPopup_Encounter`) and a separate shop flow (`UIPopup_Shop`).

Debug visualization for the hex grid (overlay drawing in the Scene view, reachability/cluster analyzers, a dedicated debug window) is provided by the generic `hp55games.Tools.HexDebugFramework` package and adapted to MapGame via `Assets/MapGame/Features/HexDebugAdapter/` (`MapGameHexTopology` implements `IHexTopology` over the real grid; analyzers under `HexDebugAdapter/Analyzers/` implement `IHexAnalyzer` for MapGame-specific checks like reachability and event-cluster spacing/budget). When adding a new hex-grid analysis or debug visualization, prefer adding an `IHexAnalyzer` in `HexDebugAdapter/Analyzers/` over ad-hoc `Debug.Draw*`/`Gizmos` calls scattered in gameplay code.

### Content & config

Non-code game data (level configs, tile configs, event clusters, HUD icon sets) lives under `Assets/MapGame/Content/`, loaded through `IConfigService`/`IContentLoader` (Addressables) rather than `Resources.Load` or direct references, except for `Assets/Resources/Localization`.

## Conventions

- Namespace roots: `hp55games.Mobile.Core.*` for template/core code (per-subsystem: `.Architecture`, `.Audio`, `.UI`, `.Content`, `.Save`, `.Pooling`, `.Timing`, `.InputSystem`, `.Context`, `.Localization`), `hp55games.MapGame.Features.*` for game-specific code, `hp55games.Addr` for Addressables key constants. Match the existing namespace of sibling files in a folder rather than assuming a pattern.
- Some existing comments/docs are in Italian (e.g. `Addr.cs`) — this is pre-existing repo content, not a signal to switch languages; match the file you're editing.
- Async operations (scene loads, state transitions, addressable loads, popups/overlays/toasts) are `Task`/`Task<T>`-based (`Task.Task`-awaiting on Addressables handles) or `IEnumerator` coroutines for the bootstrap sequence specifically — check the surrounding file to see which pattern it already uses.
- Tests: `Assets/Tests/EditMode/` (NUnit, e.g. `CorePresenceTests` reflection-checks that canonical service implementations exist by fully-qualified name) and `Assets/Tests/PlayMode/` (smoke tests per service: bootstrap flow, music, options, overlay, popup, toast, content). Keep new tests in these folders, separated from game scenes, matching the existing per-service smoke-test style.
